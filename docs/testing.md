# 验证与证据

## 证据类别

请将以下各类声明区分开：

1. **源码检查：** 代码中存在某条路径或守卫。
2. **主机测试：** 某个选定的纯逻辑/有状态单元测试连同其桩件通过。
3. **ARM 构建：** 已配置的交叉编译器链接出一个镜像。
4. **烧录校验：** 编程器针对确切的镜像报告校验成功。
5. **硬件试验：** 开发板在记录的起始条件下运行，且日志支持该结果。
6. **竞赛验收：** 由用户确认或竞赛证据确立验收结果。

通过较早的层级并不意味着通过较晚的层级。历史测试文件不能作为完整覆盖的证明。

要在一个干净的检出中准备运行器的 Python 侧，请将固定版本的模拟器依赖安装到被忽略的构建目录中：

```powershell
python -m pip install -r tests/requirements.txt --target build/testdeps
```

设置 `ARM_GCC_ROOT` 后，逐个运行这四个 PowerShell 脚本。C 测试框架会编译为 `tests/` 下被忽略的 `.elf` 文件；无需连接硬件。2026-09-24，四个运行器全部通过：按键输入 9 项检查、遥测 14 项、Q5 5,664 项、Q6 target 235 项、Q6 static-image 39 项，零失败。一次 ARM Debug 构建也通过了（Flash 100,968 / 131,072 字节；SRAM 17,672 / 32,768 字节）。这些检查不能替代烧录或硬件测试。

## 台架与竞赛变体

`user/app/q6/q6_config.h` 定义了 Q6 任务选择、静态台架模式、自动启动、启动自动选择和显式目标的默认值。这些是不同的固件变体。台架镜像可以在没有正常按键序列的情况下启动/运动；烧录前请核验 CMake 缓存和预处理定义。切勿将静态台架二进制当作竞赛镜像。

## 硬件测试记录模板

对每一次未来的试验，记录：

- 源分支与提交、脏文件清单、镜像哈希与构建宏集；
- 开发板、执行器固件、接线、供电与机械支撑；
- 起始球位置/状态、所选任务、按键/启动序列与目标；
- 测试时长与条件；
- 日志、停止原因、跟踪误差、峰值执行器指令、视觉帧间隔与故障；
- 结果属于用户报告、日志支持，还是独立重复。
